# Paper document v3 and the block editor

**Status.** Accepted 2026-11-02. Tracked under #857; the document and its upgrade are #858. Decisions 4 to 6 amended 2026-11-02 in #865, which also ships the Yjs spike. Builds on `docs/adr/0010-one-typed-contract-for-commands-and-reads.md`.

**Context.** Paper edits text with a hand-written contentEditable over plain strings. It has no marks, Enter does not split a block, there is no Cmd+Z, an IME confirm fires Enter actions and paste is not cleaned. Its one write, `paper.replace`, sends the whole document under a version check. A Coach edit during typing becomes a conflict banner, an autosave can drop keystrokes, and Coach Undo fails after any later save. Stored rows come in three shapes: CV v1 (form fields), CV v2 (blocks) and letters (`{ markdown }`). The domain must stay pure TypeScript and zod, server readers run without a DOM, and every write goes through the command path of ADR 0010.

**Decision.**

1. **The editor is BlockNote, MPL core only.** `@blocknote/core`, `react` and `shadcn`, pinned exactly and imported only inside the Paper editor folder and `packages/paper-crdt`, which holds the one block config list and the mapping between editor blocks and document v3. `@blocknote/xl-*` packages are banned, and `scripts/blocknote-dependencies.test.mjs` fails on one or on an unpinned `@blocknote/*` version. The editor is a view; it never defines the stored shape.
2. **The domain owns the stored truth: document v3.** `packages/domain/src/paper-doc` holds one typed JSON document per paper. A CV is `{ version: 3, kind: "cv", header, blocks, clashes }`. A letter is `{ version: 3, kind: "letter", blocks, clashes }` with prose blocks only. `blocks` is one flat ordered list. A `section` block is a marker; its prose and entry blocks follow it, and `sectionsOf` derives the grouping for print. Text is `RichText`: normalized runs `{ text, bold?, italic?, href? }`, where `href` is http, https or mailto. Inline markdown is accepted at the zod boundary and normalized to runs. `paperNodeSpecs` is the single node table (schema, blank, slash label, turn-into, plain text). One invariant check holds the whole shape: unique ids, fixed header id, list depth at most 3 (bounded by the schema itself, so a deep chain is refused without recursion), entries only after a section marker, and clash offers that fit the document kind and the node they name. The stored document sets no cap on text length, block count or skill items, because the old shapes had none and an upgrade never refuses a row the old editor could store; the wire in the later steps caps what the Coach and a patch send.
3. **Every stored shape upgrades on read.** `upgradeStoredPaper` turns CV v1, CV v2, letter markdown and v3 into v3, keeps v2 block ids that are valid, derives ids deterministically for v1 and letters, and returns a typed refusal for anything else. An upgrade never loses or changes a word the person typed. The old editor shows a letter's `markdown` field as plain text (`apps/web/src/features/paper/letter-sheet.tsx` ReadSheet renders each `paragraphsOf` piece verbatim), so a letter upgrades as plain paragraphs split on blank lines, with single newlines kept and no markup read. A v1 CV upgrades directly, one skills block per group, and skill items are never split. Running it on its own output changes nothing.
4. **Paper content is a Yjs document.** Each paper's content is a Yjs document (a CRDT) in the shape BlockNote's collaboration layer uses. The server keeps an update log plus a compacted base, and materializes the typed v3 document in the same transaction as every write, after checking it against `paperDocumentSchema`. Every reader (print, share, Coach outline, checks) reads v3 and never sees Yjs. The person's typing, the Coach and server inserts are Yjs transactions with distinct origins, so they merge by block id and by character. A write on a fork reconciles blocks by id (a block present on both sides is edited in place, a missing one is deleted, a new one is inserted, and a move is a delete plus an insert) and edits a matched block's text with a character diff, so the person's typing, deletions and marks between the Coach's far-apart changes survive. A `skills` block holds one child item node per skill, so items keep commas, middle dots and spaces; an item the person empties is dropped on read. The client and server exchange state vectors and missing updates over plain HTTP commands, so a resent push is harmless and no socket is needed.
5. **Coach edits run on a fork, and Undo is per origin.** The Coach edits a fork of the document at the revision it read, writes only the differences (blocks matched by id, text by a Myers character diff, and `updateYFragment` from `y-prosemirror` only to build a new block, never a hand-built copy of BlockNote's ProseMirror layout), and the server merges that update into the live document, so the Coach can write while the person types. Coach Undo replays the log into a document with garbage collection off, tracks only that edit's origin with a `Y.UndoManager`, and undoes it. It removes exactly the Coach's characters and blocks, restores what the Coach deleted, and keeps the person's later typing, even inside the Coach's sentence. Typing that reached a block the Coach had already deleted comes back with the block, whichever arrived first. Running the same undo twice changes nothing the second time. Undoing an earlier Coach edit under a later one that built on its text is not supported. It works after a reload and after any number of later saves. Cmd+Z in the browser stays the editor's local history for the person's own typing and structure.
6. **No clash cards.** A merge drops no character the person typed and kept, so nothing needs a card. The one loss is typing into a block the Coach deletes or moves, which the Coach step's freshness check must refuse for any block changed since the Coach's read. The `clashes` list stays in the v3 schema for stored rows and is always empty; seeding a document that holds a clash is refused, and a later change removes the list. This replaces the earlier choice of block patches with a compare-and-set loop and clash cards, and the earlier rejection of Yjs. The choice was judged by what feels like Notion: invisible letter-level merges, the Coach writing while you type, exact Coach undo, and offline and multi-tab catch-up. The earlier doubt was that a headless editor on the server was unproven. The spike in `packages/paper-crdt` settled it: a never-mounted `BlockNoteEditor` from `@blocknote/core` 0.57.0 converts a `Y.XmlFragment` to blocks and blocks to ProseMirror nodes, and `updateYFragment` writes the diff, all in vitest's `node` environment with no `document` or `window` and no jsdom, so `@blocknote/server-util` is not needed. What this costs: a growing log with compaction, opaque update bytes in one command the domain cannot fully type (checked before anything is stored), last-writer-wins on short CV fields (guarded for the Coach by a freshness check), and a line break taking the style of the text before it.

7. **Storage until the cutover (#872).** The Yjs log (`paper_doc_updates`) is the truth once a row is seeded. Each commit writes the update row, the v3 snapshot in `paper_docs.crdt_document` and, in `paper_docs.document`, the old shape (CV version 2 blocks, letter `{ markdown }`) that `legacyPaperOf` projects from v3, all in one transaction. `content_version` is the seq of the last folded row. Print, share, the library and the account export read `paper` (#1042). Only the old editor still reads `document`, until the cutover step removes it. Marks and links drop to plain text in the projection. A write that came from the old editor stores that exact document, so letter parts and list blocks survive. `paper.replace` merges the old editor's save onto the v3 paper (`mergeLegacyEdit`), so a save that changes nothing writes nothing and v3-only content is not erased. Section titles, heading levels, marks and links live only in `crdt_document` until the cutover, and readers that need them read `crdt_document`.

8. **Coach edits (#880).** `paper.edit` takes `basedOn` and a list of ops addressed by block id: `setText`, `setFields`, `setHeader`, `insert`, `insertInto`, `move` and `remove`. Text merges into the live block. Another op on a block or field the person changed since `basedOn`, or on a block they deleted, moved or retyped, returns `stale` and is not applied. `paper.revertEdit` undoes one edit by its id and keeps later typing. Before a Coach edit is committed the merged result is checked: every applied op must be visible in it and nothing the person typed since `basedOn` may be gone, else nothing is written and the ops come back `stale`. Undo works on Yjs item identity for the Coach's words and on the documents before, after and live for structure, so a moved block goes back with the person's later typing, a block the Coach added keeps only the person's characters, and an undo is refused when the person changed the Coach's words since. Typing that reaches the server inside a block a Coach move or remove rebuilt is absorbed like any update and is not carried by the server, because Yjs drops the dead content it would need. The step 5 client rebases its pending edits by block id across each server reply, and the person's concurrent work wins over a Coach remove. A person sync whose merge breaks a document rule is repaired by the server in the same commit, never refused. The feed may offer Undo for an edit whose words the person changed; the click then refuses with a reason. Undo of an edit is also refused, and shown as unavailable in the activity read, while a newer, not undone Coach edit built on it changed one of the same blocks. `paper.replace` is no longer a Coach tool.

9. **The letter editor (#916).** Every client push is guarded by the revision it is based on. The server absorbs a push only at that revision. Otherwise it answers stale with exactly what the client lacks and absorbs nothing, so the server never merges two concurrent person updates. The client keeps a replica of the last acknowledged server state next to the editor document. When a reply holds foreign content and the person has pending edits, it merges whole documents (base, ours, theirs) by block id and by word, then writes the result into the editor document. A closing check keeps every block and word the person added exactly once and puts the person's version beside the live one rather than lose it. Two insertions into one gap stay whole, theirs first, and only an echo of the person's own text is merged. A block one side joined into another or split in two is followed by the other side's change to its words. When both sides edit the same word, both versions are kept. The person's bold on a word the Coach deleted goes with the word. A type or heading level change merges like any field, and fields that belong to a type come from the side whose type wins. If the merge still cannot be built, the client keeps the person's moves and deletions, places a copy of each block whose typed words are missing right after the original, and shows Not merged. If even that cannot be built, it takes the live version and places a copy of each block the person changed right after its original, so neither side's words are lost. Four composite shapes can keep words twice: a block both sides restructure differently; a block one side joins or splits and then edits inside while the other side edits that block; a join chained onto a join the other side made; and a join or split of a block the Coach removed and Undo restored while the push was in flight. When the other side joins or splits a block, the person's bold on a word in it can be lost, though the word stays. No typed word is lost in any of them. Following these by word order rather than a contiguous run is #981. The editor blocks nesting past three, children under non-list blocks and heading levels outside 2 and 3, so the server repair never rewrites what the person did. The editor menus are built from the kit, not from `@blocknote/shadcn`.

10. **Old editor undo (#1041).** An activity recorded by `paper.replace` is refused by an undo guard, with no data migration. A later command that reuses the `paper.replace` or `paper.restore` reversal, including `paper.attachPhoto`, still undoes. A block the person edited survives a Coach remove with the person's copy of its fields, which puts back a Coach field edit made on that block before the remove. Both merge property models cover CV shapes.
11. **The CV editor (#1044).** CV blocks are React views over `paperBlockConfigs`, so a missing view is a type error, and the web ProseMirror schema matches the server schema. Short fields are one input bridge: each change is one `updateBlock`, the caret stays, Cmd+Z and Shift+Cmd+Z use the editor history, Enter moves to the next field or opens the first bullet, Backspace on an empty field moves back, arrows leave the row, Tab moves between fields, an IME composition does not act, and a paste keeps the first line. `cv-rules` keeps the header first and fixed, entries after a section marker, list depth at most 3, and no children under a paragraph, heading or section, and it coerces a paste to CV blocks, so the server repair does not rewrite a document the person made. Dragging a section marker moves that marker and every block up to the next section. Slash and block menus follow the document kind. The header has no side menu and cannot be deleted or moved. Deliberate differences from the pen: no underline, because v3 text has bold, italic and a link only; phone hit areas are 44px; "Role, company" is two inputs joined by a comma, and a comma never splits a field.

**Consequences.** Server readers (print, share, Coach outline, checks) read v3 with no DOM and no third-party schema. BlockNote is pre-1.0 and about 190 KB gzip on the lazy Paper route, so each upgrade is its own change, gated by a codec round-trip suite. Pre-cutover Coach activities lose Undo; today they already fail after any human save. The log grows until compaction, which must keep every edit the Undo window can still revert. The cutover rewrites every stored document with the same upgrade function and is a data-changing migration, so it carries `needs-human-review`. Until then `packages/domain/src/paper-blocks` and `paper.replace` keep working beside v3.
