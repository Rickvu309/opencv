# Coach runtime: AI SDK loop over the Command registry, SSE, parts persistence

The Coach becomes a real LLM agent. These are the load-bearing choices; supersede only with a follow-up ADR.

**Toolkit: Vercel AI SDK `streamText` + OpenRouter.** The runtime is `streamText` from `ai` with `stopWhen: stepCountIs(8)` and a max-output-token bound, consuming `fullStream` server-side; the provider is `@openrouter/ai-sdk-provider`. Model routing is User-selectable Free / Light / Max — see **ADR-0009**. `COACH_MODEL` is a deprecated single-model fallback only. A missing `OPENROUTER_API_KEY` degrades gracefully: the app boots, the coach route serves 503 `COACH_UNAVAILABLE`.

**Tools are the registry — with one recorded exception.** The mutation tool surface is derived mechanically: `commandRegistry.list().filter(coachAllowed && !destructive)`, zod input schemas reused as tool schemas, tool names mapping `.`→`_` for provider grammars. Each tool's `execute` calls `registry.execute` with `actor: { type: "coach", userId }` and returns the **full envelope** — the model sees real success and real failure, which is ADR-0003's honesty rule mechanized. The exception: `threads.postMessage` is coach-allowed but excluded from the tool surface — the stream itself is the Coach's reply channel, and that command's meaning is "the user posts a message"; a Coach calling it would fabricate user speech. Reads (`paper_listDocs`, `paper_getDoc`, `apply_listCards`, `profile_get`) are a parallel read-tool table reusing the existing query mappers, not registry commands — reads don't wear the mutation contract (reversal, updatedAt, POST exposure). Parity's real value is kept by one enumeration point: `coach/tools.ts` assembles the whole surface and a test asserts it exactly. Read DTOs equal the GET DTOs, so the Coach can never see more than the User (fit stays excluded).

**Destructive Commands (QVE-148).** User-fired deletes confirm in the UI (Home History / Thread, Paper, Apply) and do not run on dismiss. The tool builder's `!destructive` filter is **temporary**: it stays until a Coach tool call can pause for that same confirm instead of executing. Do not lift the filter without that pause. The registry also refuses `actor: coach` on any `destructive` Command (even if `coachAllowed` is later flipped), and `executeCoachMutation` returns `COACH_NOT_ALLOWED` without calling the handler.

**Transport: a minimal owned SSE protocol.** `hono/streaming` `streamSSE` emits `message-start`, `text-delta`, `tool-call`, `tool-result` (human summary + `ReversalDescriptor`), `message-end` (final persisted message + usage), `error`. The web consumes it with an `apiStream` sibling of `apiFetch` and a small parser. `@ai-sdk/react` `useChat` was rejected: it owns message state and would fight the landed thread store (React Query cache as truth). **QVE-179 spike — adopt:** `@assistant-ui/react` `ExternalStoreRuntime` (pinned `0.15.16`) is the inverse of `useChat`. The adapter (`useCoachExternalRuntime`) passes the already-derived `useCoachTurn.messages` array through a pure `convertMessage` projection and forwards send / stop / regenerate / thumbs. It does not call `setMessages`, does not keep a parallel list, and does not take the React Query cache. Home still uses `ThreadView`; Paper `CoachFloat` is the only absorb surface. `message-start` is emitted immediately to flush headers through the Railway proxy; 15-second heartbeats; no compression on the route.

**Persistence: parts on messages, telemetry apart, no draft rows.** `thread_messages` gains `parts jsonb` (ordered text/tool parts on coach messages), `status` (`final | error | aborted`), `worked_ms` (server-measured); `text` remains the canonical concatenation so existing consumers keep working. The user message commits **before** the model call; the coach row is inserted exactly once at stream end — including the abort/error path, because executed tools are committed facts and their receipts must survive. `coach_usage` (model, tokens, cost estimate, latency, finish reason, thumbs rating) keeps telemetry out of content rows and doubles as the rate-limit counter and the feedback sink.

**Budget: per-user daily turn cap.** `COACH_DAILY_TURN_LIMIT` (default 50) checked against `coach_usage` before each model call → 429 `COACH_LIMIT_REACHED`. Per-turn spend is bounded by the step cap and output-token limit. Dollar budgets are a follow-up; turn caps need no price feed.

**Prompt: pure functions.** Persona system prompt encodes the PRODUCT.md voice (grounded mentor, evidence over encouragement — cite what was read or done, exactly one next step, honest about distance, no exclamation marks). A compact workspace summary (counts + capped lists) is injected per turn; detail comes through read tools. History windows to the last 40 messages within a character budget; past tool parts flatten to bracketed text lines. Everything is unit-testable without a model.

**Runtime port.** `CoachRuntime.streamTurn(...): AsyncIterable<CoachStreamPart>` is injected via `AppConfig.coach?` like `db` — the route owns auth, limits, persistence, and SSE translation, so fake-runtime tests exercise the real protocol and CI burns zero tokens. The eval harness (golden scenarios, deterministic honesty checks, cheap LLM judge) is a manual script, never CI: `pnpm --filter api eval` before merging persona or prompt changes. `COACH_EVAL_MODE=free|light|max|all` scores each ADR-0009 default through the same `resolveCoachModel` map; it does not add a fallback chain.

**Paper panel.** Paper uses the same `CoachDock` and `useCoachTurn` as Home (Spec 7). The editor talks to the same route, runtime, tools, persistence, and mode resolution — Paper has no mode picker; it inherits the saved preference (ADR-0009). `threads.focus_doc_id` plus an optional `focusDocId` on `POST /api/threads/:id/coach` name the open document in the workspace snapshot so advice can cite it; edits still go through Commands and receipts. There is no Paper-only prompt or tool surface.

**Must-edit (QVE-178 / QVE-184 / QVE-188).** When the User asks to change, rewrite, shorten, tailor, or fix content in the focus document — or names a Paper document they own — the Coach must attempt `paper.updateContent` (after `paper_getDoc` / `paper_listDocs` for ids; `paper.createDoc` for a new document). Asking how or whether to edit is advice, not that ask — do not force a mutation. Asking to rewrite *is* consent: never draft-then-ask, never tell the User to paste. A prose-only reply is allowed only after a failed tool receipt: one plain line on what failed, one next step. The open document's current JSON and a section outline are injected on the snapshot so an edit can run without a selection or a prior `paper_getDoc`. The runtime `prepareStep` forces `paper_updateContent` (or list→get→update for a named doc) until that Command is attempted. The eval harness threads an optional `focusDocId` into the turn so this rule can be scored.

**Out of scope here:** Coach-paused destructive tool calls (the temporary `!destructive` filter; User confirm is live — QVE-148), one-click reversal from receipts, Vietnamese-first prompt / i18n (ADR-0008 / QVE-150). Multi-model routing landed in **ADR-0009**. Regenerating the latest Coach turn (new streamed row, prior row and receipts stay, current mode + daily cap) landed with **QVE-147**. Paper AI-panel unification landed with **QVE-146**.
