# The AI-native backend: one registry, one activity table, the Coach as a client

**Status.** Accepted 2026-10-26. Synthesized by the release-one program from two independent designs (domain first and agent first). Implemented by #372; #373, #376, #377, #378 and #380 add their entries to the same registry. Amended by `docs/adr/0010-one-typed-contract-for-commands-and-reads.md`. Commands and reads are now declared in `packages/domain` and bound in the api, and `compat/` is deleted. Where items 1, 4, 11 and 12 disagree with ADR 0010, ADR 0010 holds.

**Context.** The api had one command bus for writes, separate read routers per surface, a hand-copied tool list for the Coach, two refusals that kept every destructive command away from the model, no activity record, last-write-wins document saves, and tables under `openpath_app` named for a product that no longer exists. The operator's intent for release one: the Coach can do every action a person can do, so chatting is enough; Free plan runs on OpenRouter free models and Pro on Claude; the backend is redesigned, not patched.

**Decision.**

1. **One registry, one write path.** Every product action is a command entry: `name`, `description`, zod `input`, `coach` access (`auto`, `confirm` or `never`), `destructive`, `reversal`, `step(input)` label, `activity(input, output, actor)` summary, `handler`. Reads are query entries with `coach: boolean` and a `step`. The registry exposes `execute`, `read` and `tools(actor)`. `POST /api/commands/:name` and the Coach's tools both call `execute`. No module writes another module's state except through `execute`. `defineCommand` refuses `destructive` together with `coach: "auto"`.
2. **Activity is the only history.** The registry writes one `activity` row per command whose `activity()` returns a record (a person's autosave returns none; a Coach edit returns one). The row holds actor, command, subject kind and id, summary, detail, the reversal command and input, `undone_at` and an idempotency key. The job feed, the chat receipt and every Undo read this table. Notes on a job are activity rows. `activity.undo` runs the stored reversal once as the person and sets `undone_at`.
3. **Confirm inside a chat.** A `coach: "confirm"` command's tool inserts a `pending_actions` row (parsed input, summary) and returns `{ pending: true, pendingActionId, summary }` without touching data. The turn emits a `confirm` event and continues; the composer stays usable. `actions.approve` runs the stored command with the pending id as the idempotency key and records actor `coach`; `actions.deny` closes the row. A button on a screen never creates a pending row; the screen's dialog is the person's confirmation. Destructive commands (`paper.delete`, `job.delete`, `chat.delete`, `account.delete`, `inbox.send`) are `confirm` or `never` for the Coach.
4. **Modules.** `apps/api/src`: `registry/` (execute, read, tools, approve, undo, idempotency, activity, pending), `account/` (user row, plan gate, usage windows, notify, export, delete), `chat/`, `paper/`, `job/`, `inbox/`, `coach/` (the only importer of the AI SDK and the providers; the prompt, steps, SSE turn), `auth/` (better-auth, otp, Google, mail sender), `compat/` (temporary translators for the routes the current web calls, one file per surface naming the PR that deletes it), `db/` (schema and the migrator), `app.ts` (mounts), `index.ts` (composition root). Each product module has `index.ts` (the only import surface), `commands.ts`, `queries.ts`, `http.ts`, `store.ts`. `packages/domain/src`: `registry.ts`, `chat.ts`, `paper.ts`, `job.ts`, `inbox.ts`, `account.ts`, `usage.ts`, `envelope.ts`, `ids.ts`, `index.ts`; pure, no drizzle, Hono or AI SDK import. A test fails on an import that reaches past a module's `index.ts`.
5. **Schema `opencv_app`, fresh.** One squashed journal starting at `apps/api/drizzle/0000_opencv_app.sql`. The migrator records applied files in `opencv_app.migrations` (`migrationsSchema` and `migrationsTable` set inside one `runMigrations(db)` used by PGlite and Postgres; a test asserts the config and that an old `drizzle.__drizzle_migrations` journal is ignored). Nothing reads, alters or drops `openpath_app`; the operator drops it by hand after the release is live. better-auth binds to `opencv_app.user`, `session`, `account`, `verification`; profile columns live on `user`. Tables: `user` (plus `plan`, `coach_mode`, `language`, `time_zone`, `start_page`, `notify_email`, `notify_browser`, `memory_enabled`, `agent_chat`, `agent_cvs`, `agent_interview`, `agent_email`, `agent_weekly`, `welcomed_at`, `inbox_skipped_at`), `session`, `account`, `verification`, `chats` (`focus_kind`, `focus_id`), `chat_messages` (`parts` jsonb, `status`, `worked_ms`), `pending_actions`, `activity`, `paper_docs` (`kind` cv or letter, `template_id`, `document` jsonb holding today's section codec, with the block document arriving in #379 under `content_version` compare-and-swap, `checks`, `page_choice`, `source_file_id`), `files` (`purpose` import or avatar, `bytes` bytea, 8 MB cap), `paper_shares`, `jobs` (`title`, `company`, `stage`, `position`, `location`, `priority`, `job_url`, `source_host`, `description`, `posting` jsonb, `interview_at`, `deadline`, `recruiter_name`, `recruiter_email`, `cv_doc_id`, `letter_doc_id`, `starred`), `job_checklist`, `connections`, `inbox_threads`, `inbox_messages`, `coach_usage` (plan, mode, provider, model, finish reason, latency; no rating, no token counts sent to the client), `notify_requests`. No pitch table, no `demo`, no `fit`, no `track_kind`.
6. **Words.** Commands are `chat.*`, `paper.*`, `job.*`, `inbox.*`, `profile.*`, `account.*`, `notify.request`, `actions.approve`, `actions.deny`, `activity.undo`, `coach.stop`. Stages are `saved`, `applied`, `interview`, `offer`, `closed`. The Job owns its Paper links (`cv_doc_id`, `letter_doc_id`) through `job.linkPaper` and `job.unlinkPaper`.
7. **The Coach is a client.** At the start of a turn, `registry.tools(actor)` is the whole tool list, filtered by the profile's agent toggles (`agent_cvs` gates `paper.edit` on a CV, `agent_interview` gates checklist commands, `agent_email` gates `inbox.scan` and `inbox.draftReply`). Tool names replace `.` with `_` in the coach module only. Steps come from each entry's `step`. Attachments on a turn (`paper`, `job`, `link`, `file`) resolve through `registry.read`; bytes never enter the prompt. A chat carries one focus (`paper`, `job` or `inbox`); the turn loads it unless the request overrides it. `memory_enabled` gates the titles of the last ten chats in the prompt. A focused edit is `paper.edit` (ADR 0011 decision 10). The 2026-10-26 text named `paper.replace` for that gate and for the free-mode ending; that command is gone. The repair and rewrite layers stay deleted.
8. **Plans, models and usage.** `plan` (`free`, `pro`) and `coach_mode` (`free`, `light`, `max`) live on `user`. `routeCoachModel({ plan, mode })` is the only function that constructs a model: free plan on OpenRouter `openrouter/free` (`COACH_MODEL_FREE`); pro plan on Anthropic through `@ai-sdk/anthropic` with `ANTHROPIC_API_KEY`, free mode `claude-haiku-5-5` (`COACH_MODEL_PRO_FREE`), light `claude-sonnet-5-5` (`COACH_MODEL_LIGHT`), max `claude-opus-5-5` (`COACH_MODEL_MAX`). Ids are configuration. Light and Max on a free plan return `PLAN_REQUIRED` (402). The blocking window is the day starting at 07:00 in the profile time zone with caps `COACH_DAILY_TURN_LIMIT_FREE` 20, `LIGHT` 10, `MAX` 5, `PRO_FREE` 0 (0 means uncapped). Sessions are aligned blocks of `COACH_SESSION_HOURS` (default 4) starting at 07:00 in the profile time zone, the block that contains now supplies the turn count, and `resetsAt` is the block end. The week starts Monday at 07:00. Both are display percentages. A turn counts when the stream opens. Title generation and `job.preview` use the router at the person's plan with free mode and do not count. The 429 body carries `resetsAt`, `window`, `mode`, `plan` and a message that names the reset time. `GET /api/coach/usage` returns `plan`, `mode`, `session { capped, percent, resetsAt }`, `day { capped, used, cap, remaining, resetsAt }`, `week { capped, percent, resetsAt }`; an uncapped window sets `capped: false` and omits the numbers.
9. **Auth and mail.** #373 adds `emailOTP` (6 digits, 300 s, hashed, first code creates the account), the Resend sender behind `RESEND_API_KEY` and `AUTH_EMAIL_FROM` with the log sender otherwise, `genericOAuth` for Google registered only when both Google env values exist, `GET /api/public-config` returning `{ google: boolean }`, `welcomed_at` for the welcome page, and change-email through the plugin. Session expiry is the existing 401; the client shows the overlay. #372 leaves the auth module ready for those plugins and binds it to the new schema.
10. **Inbox.** `MailProvider` is a port in `packages/domain/src/inbox.ts` (`listThreads`, `getThread`, `send`, `createEvent`); the inbox module binds it to one `connections` row and tokens never leave the store. The fake provider ships six fixture threads for local runs and verification; the Gmail provider exists behind `GMAIL_ENABLED` and the Google client. A matched interview message sets `suggested_stage` on the thread; `inbox.acceptSuggestion` runs `job.move`. `inbox.send` and `inbox.addToCalendar` are person-only. #372 creates the tables and the port; #380 implements the commands and providers.
11. **Http.** Writes are `POST /api/commands/:name` with `{ input, idempotencyKey? }`. Reads: `GET /api/chats`, `/api/chats/:id`, `/api/paper`, `/api/paper/:id`, `/api/paper/shared/:token` (public), `/api/jobs`, `/api/jobs/:id`, `/api/jobs/calendar`, `/api/inbox`, `/api/inbox/:id`, `/api/activity?subjectKind&subjectId`, `/api/profile`, `/api/coach/usage`, `/api/integrations`, `/api/billing`, `/api/account/export`, `/api/search`, `/api/public-config`. Non-JSON exceptions: `POST /api/chats/:id/turns` (SSE), `POST /api/chats/:id/stop`, `POST /api/jobs/preview` (a read that fetches), `POST /api/paper/import` and `POST /api/account/photo` (multipart), `GET /api/inbox/connect` and `callback` (redirects). SSE events are the `ChatTurnEvent` union: `message-start`, `text-delta`, `step`, `tool-call`, `tool-result`, `confirm`, `usage`, `message-end`, `error`.
12. **Compat.** A compat layer (deleted in #418) kept the routes and command names the current web calls working on top of the registry until the surface PR that rebuilds that screen deletes the file: threads (#377), apply with the stage map inbox and prep to saved, sent to applied, live to interview (#376), paper on the old route shapes (#378), profile (#375). Pitch gets no compat: #372 removes the Pitch api, tables, domain codecs, starter content and web feature and mounts a plain placeholder page that #381 replaces.
13. **No starter content.** The user-create hook writes profile defaults only. First run shows the empty states the design draws. Verification flows create their own data.
14. **Deleted.** `pitch/` and `features/pitch`, `threads/`, `starter/` sample content, `coach/must-edit*`, `free-must-edit`, `must-edit-repair`, `rewrite`, `replacement-text`, `pitch-scope`, `apply-card-guard`, `focus-doc`, `reads`, `tool-dump`, `eval/`, `smoke*`, `COACH_READ_TOOLS`, the feedback and reverse routes, `coachAllowed`, `demo`, `fit`, `track_kind`.

**Consequences.** Adding a product action is one `defineCommand` in one module; the button, the Coach tool, the step label, the activity line and Undo follow from it. The api is empty of sample content, so the first-run screens carry the onboarding. Production looks empty after the deploy because new rows live in `opencv_app` and nothing copies from `openpath_app`; that is the reset the operator chose, and no data is deleted until the operator drops the old schema. Model ids and caps change through environment variables, never through code. The Gmail provider cannot be verified live until the Google client exists; the fake provider is the verification path. The weekly plan agent has no scheduler; the shell starts it when the person opens the app on a Monday.
