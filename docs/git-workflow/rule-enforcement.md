# PR workflow rules and what enforces them

The rules in `AGENTS.md` sections 1 to 6. The table between the markers is generated from the ocv-tools rule table. `scripts/ocv-tools.mjs rules --check` fails when that block is stale, and `--write` refreshes it. A judgment row says Nothing in the jobs column: a reviewer applies it, and a script cannot.

The checks live in `scripts/lib/rules.sh`; `scripts/test-rules.sh`, `open-pr.test.mjs`, `test-merge-pr.sh` and
`take.test.mjs` each reproduce the violation and assert the refusal. A fix that changes a branch starts with `cd <worktree>`.
Skipped, not blocked: a clone whose hook never stamped (no `.git/pre-push-stamps`
directory) and a worktree created before `ocv-tools take` recorded its port. A branch cut before the stamping hook landed is blocked:
its worktree runs its own old `.githooks/pre-push`, so only a rebase onto `origin/main` fixes it. The stamp files are never deleted
and anyone can write one with `touch`; they catch a skipped hook by mistake, not a forged stamp.
The `heavy` wrapper and its rule were removed in #591.
scripts/review-pr.sh was removed in #600. A pull request merges when the ci check is green.

Runner safety. `ci.yml` runs on GitHub-hosted runners. The repository is private, the workflow has only `contents: read`, and PR code runs in GitHub's sandbox rather than on the owner's machine.

Not enforced yet, and why: splitting long work into sub-issues (a size judgment), verify evidence before `gh pr ready` (run a verify skill by hand; nothing checks it at merge), never approving with another identity (one account), and the post-merge cleanup (`ocv-tools cleanup` is run by hand).
