# PR workflow rules and what enforces them

The rules in `AGENTS.md` sections 1 to 6. The table between the markers is generated from the ocv-tools rule table. `scripts/ocv-tools.mjs rules --check` fails when that block is stale, and `--write` refreshes it. Delivery job refusals are in [delivery rules](delivery-rules.md), and the rows the git hooks run are in [hook rules](hook-rules.md). A judgment row says Nothing in the at column: a reviewer applies it, and a script cannot.

The checks live in `scripts/ocv-tools/rules`, and `scripts/ocv-tools/rules.test.mjs`, `scripts/ocv-tools/jobs/*.test.mjs` and
`scripts/ocv-tools/take.test.mjs` assert them. A fix that changes a branch starts with `cd <worktree>`.
The git hooks are shims over `scripts/ocv-tools.mjs hook`; the `at` column lists the moments a rule runs at, and `holds against main` is `yes` when the live pull request moment (`pr`) holds it on the server.
A refusal is only ever a row fired at a moment: the runner for that moment (see [rule moments](rule-moments.md) for what each moment means and which file runs it) gathers its facts and calls `decide(moment, facts)`, and `rules/layers.test.mjs` fails on a hand-raised refusal.
PORT skips a worktree created before `ocv-tools take` recorded its port.
The `heavy` wrapper and its rule were removed in #591.
scripts/review-pr.sh was removed in #600. A pull request merges when the ci check is green.

Runner safety. `ci.yml` runs on GitHub-hosted runners. The repository is private, the workflow has only `contents: read`, and PR code runs in GitHub's sandbox rather than on the owner's machine.

Not enforced yet, and why: splitting long work into sub-issues (a size judgment), verify evidence before `gh pr ready` (run a verify skill by hand; nothing checks it at merge), never approving with another identity (one account), and the post-merge cleanup (`ocv-tools cleanup` is run by hand).
