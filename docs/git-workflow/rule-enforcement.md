# PR workflow rules and what enforces them

The rules in `AGENTS.md` sections 2 to 6, each paired with the script that checks it. A check prints one line that names the
fix and records it as `next` in the script's `result.json` (cause `hygiene`). A rule with no check is a judgment rule; the
reviewer applies it, and the last column says why a script cannot.

| Rule (AGENTS.md section)                                         | Enforced by                                                                                                                                                                                                                                                                                                      | Fix it names                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ---------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Never edit files in the main checkout (2)                        | `open-pr.sh` and `merge-pr.sh`: the main checkout must be on `main` (not detached) with no edited tracked file                                                                                                                                                                                                   | Save the edit as a patch for a worktree (`git diff HEAD > ~/tmp/...`), then `git -C <main> restore --staged --worktree .`                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Use only your assigned port (2)                                  | `new-task.sh` records the port in the worktree's git dir; `open-pr.sh` fails if `.env` has another `PORT`                                                                                                                                                                                                        | `sed -i -E 's/^PORT=.*/PORT=<assigned>/' .env`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Never touch another agent's worktree (2)                         | Judgment rule: git records no agent identity (one account, one author), so nothing tells whose hands edited a worktree                                                                                                                                                                                           | None                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Never use `--no-verify` (5)                                      | Push: `.githooks/pre-push` stamps every pushed sha; `open-pr.sh` (after its push) and `merge-pr.sh` (before the gate) refuse a sha with no stamp. Commit: `open-pr.sh` and `merge-pr.sh` re-check the branch for an attribution trailer and a file over the 20000-byte pre-commit limit                          | Push: `cd <worktree> && git fetch origin main && git rebase origin/main && git commit --amend --no-edit && git push --force-with-lease` (the rebase brings the stamping hook). Trailer: `cd <worktree> && git reset --soft "$(git merge-base origin/main HEAD)" && git commit -m "$(git log -1 --format=%s ORIG_HEAD)" && git push --force-with-lease`. Oversize file: split it as `.githooks/pre-commit` says, then `cd <worktree> && git add -A && git commit -m "fix: split oversize files under the 20000-byte limit" && git push origin HEAD` |
| Never use `SKIP_CHECKS=1` without a human-declared emergency (5) | `open-pr.sh` needs `SKIP_CHECKS_DECLARED_BY=<who>` and writes `emergency declared by <who>` in the PR body; the hook stamps `skip`; `merge-pr.sh` refuses a `skip` head whose body has no `emergency declared by <name>` (the template line about `SKIP_CHECKS` does not count)                                  | `SKIP_CHECKS_DECLARED_BY=<who>`, or `gh api -X PATCH repos/{owner}/{repo}/pulls/<pr> -f body=...` (`gh pr edit` fails here)                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Never pick up an issue labeled `ready-for-human` (5)             | `new-task.sh` and `open-pr.sh` read the issue's labels                                                                                                                                                                                                                                                           | Pick another issue                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Never add GitHub Actions workflows other than `ci.yml` (5)       | `open-pr.sh` (the branch diff) and `merge-pr.sh` (the PR diff, before the gate) refuse a path under `.github/workflows/` except `.github/workflows/ci.yml` (which may change but not vanish; a change to it, `check.sh` or the ruleset needs `risk:high` on the issue, owner `/approve` is slice 5 of epic #582) | `cd <worktree> && git rm -rf -- <files> && git commit --amend --no-edit`                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |

The checks live in `scripts/lib/rules.sh`; `scripts/test-rules.sh`, `open-pr.test.mjs`, `test-merge-pr.sh`, `test-review-pr.sh` and
`test-new-task.sh` each reproduce the violation and assert the refusal. `merge-pr.sh` runs in the main checkout, so every fix that
changes a branch starts with `cd <worktree>`. Skipped, not blocked: a clone whose hook never stamped (no `.git/pre-push-stamps`
directory) and a worktree created before `new-task.sh` recorded its port. A branch cut before the stamping hook landed is blocked:
its worktree runs its own old `.githooks/pre-push`, so only a rebase onto `origin/main` fixes it. The stamp files are never deleted
and anyone can write one with `touch`; they catch a skipped hook by mistake, not a forged stamp.
The `heavy` wrapper and its rule were removed in #591.

Why the runner is safe. `ci.yml` runs on a self-hosted runner as the owner's user, so PR code (its own `ci.yml`, `pnpm install` scripts and `check.sh`) runs on this machine before any review. That is acceptable only while the repo is private, `quanvu309` is its sole collaborator, fork PR workflows are off, and the workflow token is read-only; every PR author is already an owner-account agent running the same code locally. It breaks the moment a collaborator is added, fork runs are enabled, or a bot opens PRs. With the runner off, `ci` queues for up to 24 hours and `merge-pr.sh` refuses until it is green.

Not enforced yet, and why: splitting long work into sub-issues (a size judgment), verify evidence before `gh pr ready` (`merge-pr.sh`
checks it at merge), never approving with the review agent's identity (one account), and the post-merge cleanup (`cleanup-worktree.sh` is run by hand).
