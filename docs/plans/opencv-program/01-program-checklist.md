### PR mechanics, for every PR

- [ ] Resolve the forge once. `gh` is the forge for this program (`command -v origin` fails on this machine). Never require `gt`.
- [ ] Open the PR ready, never draft, per **Opening a PR**, with `gh pr create --base main`. Title pattern `type: description (#<issue>)` with `type` one of `feat`, `fix`, `hotfix`, `refactor`, `chore` or `docs`, and the body line `Closes #<issue>`. Every commit and PR is authored by `rickvu <minhquanvu3902@gmail.com>` with no AI trailers and no `--no-verify`.
- [ ] Run `pnpm turbo run lint typecheck build` and the touched package's tests once before the PR-facing push. Push with hooks on.
- [ ] Run `/deslop` before each commit and `/no-comments` before review.
- [ ] Triage every Bugbot and security-reviewer comment per `references/bugbot-triage.md`.
- [ ] Rebase onto current trunk before the code-ready report and babysit. Keep that merge base in fix rounds. Rebase again only at merge prep, on a `git merge-tree` conflict with trunk, or on a gates failure that comes from a change on trunk.

### Verdict and merge, for every PR

- [ ] A full swarm runs once, at the code-ready head. Another full swarm runs only for new behavior, a redesign, or a large new diff. A rebase, a merge-conflict resolution, or a minor fix gets a single verifier at the new head. Run each full swarm per `pstack/skills/swarm/SKILL.md` on `sonnet`. One gates lane (`pnpm turbo run lint typecheck build test` at the head). The ten live lanes from the PR's **Verify, live** block. The perf lane from its **Verify, perf** block. Two audit lanes, one reading the diff against the PR's **Build** boxes and one reading the receipts against the **You see** boxes, both distrusting the PR body. The root audits the receipts in the merge-ready report before the verdict.
- [ ] Clean only when every lane is `PASS`. Findings go back to the owner, including a defect that a lane filed as a note. A new head gets a fresh verdict, except for results that stay valid under the patch-id rule in `playbooks/shipping.md`.
- [ ] The owner squash-merges only what the root verified, after a rebase onto current trunk with the patch-id unchanged. The swarm's gates lane on a fresh worktree at the exact head (`pnpm install --frozen-lockfile`, then `pnpm turbo run lint typecheck build` and every package's tests) is the required check. There is no GitHub Actions CI, and the trail records the gates report path for each merge. PR-3, PR-11 and PR-17 stop at merge-ready for the operator's click.
