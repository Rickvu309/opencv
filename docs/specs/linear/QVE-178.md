## Parent

Spec 8: Paper Coach shell ([QVE-175](https://linear.app/quanvm/issue/QVE-175)).

## What to build

**Hard rule:** when the User asks to change, rewrite, shorten, tailor, or fix content in the focus doc — or names a doc they own — the Coach **must** attempt `paper.updateContent` (after `paper_getDoc` / `paper_listDocs` for ids; `paper.createDoc` for new docs). Prose-only replies are permitted only after a failed tool receipt: one plain line on what failed, one next step.

1. **Prompt** (`apps/api/src/coach/prompt.ts`) — the edit rule beside the existing selection preference; persona line + `focusDoc` instruction.
2. **Eval plumbing** (explicit scope): `GoldenScenario` gains optional `focusDocId`; seeded paper docs gain stable ids; `seed.ts` + `run.ts` thread the focus doc into the turn request.
3. **Scenarios:** ≥2 golden edit scenarios with `requireSuccessfulTool: "paper_updateContent"` — one focus-doc edit, one named-doc edit without `focusDocId` (list → get → update). Manual only: `pnpm --filter api eval`.
4. **Web E2E** (mock runtime, `threads-api-mock.ts` + `patchMockPaperDoc`): edit ask on open CV → `paper.updateContent` receipt (`detail` field) → canvas updates with no manual paste. S7.4 sync/conflict/highlight is inherited, not rebuilt.

## Acceptance criteria

- [ ] Edit request on the focus doc produces a `paper_updateContent` attempt; prose-only allowed only after a failed receipt
- [ ] Eval harness threads a focus doc; both golden scenarios pass on manual `pnpm --filter api eval`
- [ ] Web E2E: canvas updates without manual paste; failed tool → one plain line, no paste advice
- [ ] CI burns zero OpenRouter tokens; CI green (GitHub Actions is the gate)
