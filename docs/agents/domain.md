# Product and implementation context

Read `CONTEXT.md` for product vocabulary and `PRODUCT.md` for intent and open questions.
Read the relevant source and tests for current implementation. Use `docs/deploy.md`
for deployment operations and `CONTRIBUTING.md` for the development workflow.

Historical ADRs, build specs, research notes and rollout plans have been retired.
Git history retains them for provenance. They are not implementation requirements.
New work follows the current user request, GitHub issue and checked-in behavior.

Keep product terms consistent with `CONTEXT.md`. Record a new product decision in
`PRODUCT.md` and update its vocabulary in `CONTEXT.md` when necessary. Keep current
operational instructions with their existing runbook rather than duplicating them.
