# OpenCV stack assessment

Assessment date: 2026-10-30. Issue: [#640](https://github.com/Rickvu309/opencv/issues/640). Source baseline: `25aff982feb055866cfb45a184ac21b78542875f`.

## Decision

Keep the current stack and the shared command/read contract. This review found no demonstrated fivefold improvement that justifies a framework, runtime, ORM, database or hosting migration. No application change is accepted by this assessment. The alternatives below are designs for experiments, not implementation commitments.

The strongest opportunities are bounded reads, database round trips, dependency-layer caching and Coach work outside the main response. Source inspection establishes where to measure; it does not establish their production cost. Production traces, representative PostgreSQL load results, field web metrics and hosting bills were unavailable. Consequently, this report cannot establish either a fivefold gain or that the current implementation is optimal.

## Task and success condition

Assess how OpenCV actually works, compare current primary-source guidance with its constraints, and reconsider its architecture. Apply a change only when a relevant experiment demonstrates at least 5× improvement with equivalent product behavior and acceptable migration cost. A narrower measured gain must retain its narrower name: faster Job detail is not a fivefold faster app.

For latency or cost, the ratio is baseline divided by candidate; for successful throughput it is candidate divided by baseline. Specify the workload, percentile, resource budget and correctness gate before running. Do not combine unrelated metrics into an invented architecture score. Keep the best small fix in the existing stack as a competing baseline.

## Current architecture

Manifest declarations describe the intended dependencies; they do not independently verify installed/deployed versions or current security status.

| Area     | Checked-in stack                                    | Ownership and behavior                                                                                                               |
| -------- | --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| Web      | React 19.3, Vite 8.1, TanStack Router 1 and Query 5 | Client-rendered SPA, lazy routes; only `apps/web/src/lib` owns HTTP paths, read keys and invalidation.                               |
| UI       | shadcn/Base UI source kit, Tailwind 4, Sonner       | `packages/ui` owns primitives and stock tokens; design snapshots and boundary tests protect product usage.                           |
| Contract | TypeScript 6, zod 4                                 | Pure `packages/domain/src` defines commands, reads, access, idempotency and invalidations.                                           |
| API      | Hono 4 on Node, Better Auth                         | Product modules own their tables; the registry coordinates command effects, activity, confirmations and Undo.                        |
| Data     | Drizzle 0.45, pg 8, PostgreSQL                      | One production pool; request/transaction context uses AsyncLocalStorage. PGlite is a local/test driver and is refused in production. |
| Coach    | AI SDK 6, provider adapters, typed SSE              | Only the Coach module imports the AI SDK; permitted actions run through the same command registry as the person's actions.           |
| Delivery | pnpm 10.33.4, Turbo 2, affected GitHub CI           | Railway hosts API, PostgreSQL and static web; Caddy serves the Vite build with immutable asset caching.                              |

A person's command passes through `apps/web/src/lib/contract-client.ts`, authenticated registry HTTP handling and `registry.execute`. The registry validates input/access, applies confirmation and idempotency policy, invokes the owning module and records effects. The web refreshes the contract-declared reads and activity. Coach actions enter that same registry; stream events refresh the same reads. This is the key interface to preserve.

The relevant existing decisions are [ADR 0009](../adr/0009-ai-native-backend.md) and [ADR 0010](../adr/0010-one-typed-contract-for-commands-and-reads.md). This assessment retains both. The UI remains governed by [ADR 0006](../adr/0006-design-system-values-and-the-kit-as-generator.md).

## Source-grounded opportunities

These are hypotheses. None is reported as a reproduced production defect or a measured speedup.

| Observation                                                                                                                                                                                              | Smallest useful experiment                                                                                                             | Scope and correctness limit                                                                                                            |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `getJob` in `apps/api/src/job/store.ts` awaits ownership, note, checklist and conditional Paper-link reads in sequence.                                                                                  | Trace each query at realistic API–database latency; compare independent parallel reads or one projected read.                          | Measure the complete endpoint, preserve ownership and response semantics. Five possible reads do not imply 5× latency improvement.     |
| Shell recent Chats and favorites slice full lists; unread Inbox count also consumes a list. See `apps/web/src/features/app-shell/use-shell-chats.ts` and neighboring hooks.                              | Compare current requests with a bounded summary at realistic per-person sizes, including subsequent route navigation.                  | Preserve ordering, unread/favorite freshness and total route traffic; small datasets may not benefit.                                  |
| Coach reads Chat history before sending the latest 40 messages to the model. First-turn completion can also await a title-model call. See `apps/api/src/coach/http.ts` and `apps/api/src/coach/turn.ts`. | Trace admission/history cost separately from model time; trial a bounded model-context read or separate title work only when dominant. | Preserve full history access, tool-result pairing, persistence, Stop and retry behavior. Distinguish first-token time from completion. |
| `runContractCommand` awaits declared read refreshes and activity refresh. Text deltas update React state individually.                                                                                   | Trace acknowledgement and stream frame cost before considering background refresh or frame batching.                                   | Retain Undo, error reporting, cross-surface freshness and first/last-token visibility. Fewer renders alone prove no user benefit.      |
| `apps/web/Dockerfile` copies the repository before installing dependencies. Source edits invalidate that layer.                                                                                          | Compare source-only rebuilds with dependency manifests installed in a stable layer, under the same builder/store conditions.           | Measure total build/deploy time, not only the install step; preserve workspace resolution and frozen-lockfile behavior.                |
| Public pages begin as an empty SPA root; page-specific metadata is rendered by the browser application.                                                                                                  | If sharing/crawlability or initial rendering is deficient, prerender one public page and compare its HTML and throttled load.          | This source fact does not establish poor search performance and does not justify changing signed-in rendering.                         |

Source also identifies a topology constraint: Stop controllers live in one API process, as documented in `docs/deploy.md`. Multiple instances or restart/reconnect continuity would require durable turn ownership and cancellation. No requirement or fivefold benefit was established for adding that machinery now.

The inspected source does not expose request-span instrumentation, and production platform monitoring was not inspected. Start with request time, database execution/pool wait, response bytes and Coach provider time. Review real PostgreSQL concurrent command replay and turn admission separately: passing PGlite tests does not establish network/pool/lock behavior. These checks do not require replacing the stack.
