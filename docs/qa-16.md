# QA 16: final polish audit

Audit for RDS-974, the final quality pass over the whole app (docs/architecture.md
section 8, ticket 16). Method: read every flow's code end to end, walked all nine
user flows in a real headless Chromium session against the dev server, and swept
`lib/data/` for content believability. Findings below, grouped by the brief's
scope order. Each item is checked off once fixed and re-verified.

## 1. Flow walkthrough audit

Clicked through all nine flows end to end in a headless browser (onboarding,
intake, scan, understand, decide, tailor, capture, direction, proactive).

- [x] Onboarding (flow 1): welcome through Ready step through `/home` landing,
      including the "Use example" fast path. No breaks found.
- [x] Add an opportunity (flow 2): paste tab parse, preview, edit, save to
      Saved. No breaks found.
- [x] Scan and prioritize (flow 3): board and list view toggle, filters. No
      breaks found.
- [x] Understand one opportunity (flow 4): Overview, AI Analysis, Actions,
      Materials, Activity tabs all render. No breaks found.
- [x] Decide next step (flow 5): accept a next action, toast confirms. No
      breaks found.
- [x] Tailor materials (flow 6): Materials tab, tailor dialog opens. No
      breaks found.
- [x] Capture track record (flow 7): candidate review queue renders. No
      breaks found in the happy path; see empty-state gap below.
- [x] Review direction (flow 8): Goals and Skills & Learning both render. No
      breaks found.
- [x] Proactive loop (flow 9): Home nudges and Weekly Review dialog both

- [x] Direct-URL access to a nonexistent `/opportunities/[id]` and

## 2. Content believability (seed data)

- [x] Persona years-of-experience contradicted itself: `persona.summary` and
      every CV/tailoring insight said "seven years," but `persona.experience`
      entries actually span about nine years (Jul 2017 to present). Fixed by
      correcting the stated figure to nine years everywhere it appears
      (`lib/data/persona.ts`, `lib/data/cvs.ts`, `lib/data/insights.ts`,
      `docs/architecture.md` section 6).
- [x] Persona summary said "the last two years designing the AI underwriting
      assistant at Fintra," but Fintra's start date (`Apr 2023`) makes that
      about three years as of the July 2026 demo date. Fixed the summary and
      the matching line in `lib/data/goals.ts` goal-1 to say three years.
- [x] Opportunity opp-1 (Solace AI): three different, all-wrong figures for
      how long it has sat in Saved ("4 weeks" in `lib/data/nudges.ts`,
      "4 weeks" in `lib/data/copilot-scripts.ts`, "three weeks" in
      `lib/data/actions.ts`) when `savedAt` (2026-06-02) to the demo date
      (2026-07-31) is about eight weeks. Fixed all three to say eight weeks.
- [x] Opportunity opp-4 (Arclight AI): `action-2.rationale` said "No update
      in 12 days" but `lastActivityAt` (2026-07-15) to the demo date is 16
      days. Fixed to 16 days.
- [x] Opportunity opp-6 (Meridian Labs): notes said "Panel round Thursday"
      with no date, written against a `lastActivityAt` of Monday 2026-07-27.
      The nearest Thursday (2026-07-30) is a day before the July 31 demo
      date, so the panel would already be over, contradicting the still
      "scheduled" framing and the accepted (not done) prep action. Fixed by
      naming the actual future Thursday (August 6) in the note.
- [x] Stale file-header comment in `lib/data/opportunities.ts` said "9
      opportunities," the array has 10 (opp-10 was added for the ticket-15
      nudge). Fixed the comment.
- [x] Reviewed opp-7 (Brightpath Bank) "sent the thank-you note same day"
      against the activity log gap (action accepted 07-15, reflective note
      added 07-20): not a real contradiction, the "same day" refers to the
      final loop and the note being the same day, and the reflective note
      field was written five days later. No change needed.
- [x] Reviewed the goal-2 / goal-4 shared link to learning item `li-4`: the
      item's own copy explicitly serves both the recurring writing habit
      (goal-4) and the AI-explainability case study (goal-2), so the shared
      link is intentional, not a copy/paste slip. No change needed.
- [x] Swept for filler, placeholder text, generic AI copy, and
      placeholder-looking names or numbers: none found. Every insight
      references its specific host object; opp-2's deliberate vagueness is
      the intentional low-credibility-posting device from architecture.md
      section 6, not filler.

## 3. Visual consistency

- [x] Shared `ExpandableRow` toggle (`components/shared/expandable-row.tsx`)
      had no hover or focus-visible feedback at all, which propagated to
      every "why this reading" disclosure across the AI Analysis tab. Fixed
      with the same `hover:` and `focus-visible:ring` treatment used
      elsewhere in the shell.
- [x] `why-this-reading.tsx` had a hover state but no explicit
      `focus-visible` ring. Added one.
- [x] "Source content, raw" disclosure in `opportunity-overview-tab.tsx` had
      no hover/focus feedback. Fixed.
- [x] Profile strengths card's expand toggle had no hover/focus state, while
      its own sibling remove button did. Fixed for consistency.
- [x] Goal card's title expand toggle had no hover/focus state. Fixed.
- [x] Non-randomized "thinking" delays: `add-opportunity-dialog.tsx` paste
      parse and `opportunity-ai-analysis-tab.tsx` refresh both used a fixed
      900ms instead of the randomized 600 to 1200ms range used everywhere
      else. Fixed both to the same `600 + Math.random() * 600` pattern.
- [x] Normalized the ad hoc "muted info/callout box" padding
      (`rounded-lg border ... bg-muted/NN`) that had five different padding
      values across goals/, onboarding/, opportunities/, profile/, skills/
      (`p-2.5`, `p-3`, `px-3 py-2`, `px-2.5 py-1.5`, `px-4 py-3`). Normalized
      to `p-3` throughout.
- [x] Stray ad hoc badges outside the shared chip system: credibility
      pass/fail badge and "vague language decoded" badge in
      `opportunity-ai-analysis-tab.tsx`, and the "Credibility flag" badge in
      `opportunity-summary-band.tsx`, each hand-rolled their own color
      classes instead of sharing one look. Consolidated into one
      `CredibilityChip` shared component reused in both places.
- [x] `skill-row.tsx`'s "Gap" badge reused `FitChip`'s exact rose color by
      hand rather than through the chip system. Left as a plain `Badge`
      with a code comment is not appropriate; switched it to share styling
      via the same rose token as `Chip`'s destructive tone so a future
      palette change only happens in one place.
- [x] `learning-item-card.tsx`'s "Start here" badge reused the indigo color
      that `CopilotTag`/`ConfidenceChip` use for AI-authored content, risking
      being read as an AI tag when it is not. Changed to a neutral
      `secondary` badge variant.
- [x] `profile-identity-band.tsx`'s target-direction chip used the exact same
      indigo as `CopilotTag`/`ConfidenceChip` for a plain profile fact, not
      AI-authored content. Changed to a distinct blue so only real Copilot
      output reads as indigo.
- [x] Consolidated the repeated "linked object" badge-wrapping-a-link pattern
      (Track Record entries, learning items, skill rows, goal cards, the
      direction gap analysis) into one shared `LinkChip` component instead of
      each surface hand-rolling the same `Badge variant="outline" asChild`
      wrapper.
- [x] `entry-fields-form.tsx`'s skill-selector chip duplicated
      `components/onboarding/selectable-chip.tsx` almost line for line.
      Replaced with the shared `SelectableChip`.

## 5. States

- [x] Track Record's "For your review" AI-drafted candidate section
      (`app/(app)/track-record/page.tsx`) disappeared entirely once every
      candidate was dismissed, with no designed empty state, the one
      reachable list in the app that skipped the shared `EmptyState`
      component. Fixed to show a one-line designed empty state instead of
      rendering nothing.
- [x] Confirmed every other reachable empty scenario (CV Versions fully
      deleted, Home nudges and next actions fully cleared, Copilot
      conversation history) already renders a designed `EmptyState`.
- [x] Confirmed newly created objects (a pasted opportunity, a tailored CV
      version, a confirmed track record entry) render correctly on every
      surface that lists them, with the highlight-and-scroll behavior
      already in the store.

## 6. Edge sweep

- [x] Direct-URL access to a nonexistent opportunity or CV id: both show a
      graceful "doesn't exist, or was removed" state with a link back, no
      crash. Verified live.
- [x] Refresh mid-flow: verified no `localStorage`/`sessionStorage` usage
      anywhere (state is intentionally in-memory only), reload always
      returns to a clean, non-broken initial view for the current route.
- [x] Long text in user inputs: fixed the two spots that could break page
      layout (not just get clipped inside a card): the page header title
      (fed by a pasted role name or a CV name) and the "Source content, raw"
      block now wrap instead of overflowing horizontally. Added
      `min-w-0`/`truncate` to goal card titles, track record entry/candidate
      card titles, and the direction band's target-direction text, which
      previously had no overflow handling at all.
- [x] `opportunity-list-view.tsx` had `truncate` immediately overridden by a
      later `whitespace-normal` class on the same element, silently
      canceling the single-line ellipsis. Fixed.
- [x] Below-1024px guard: confirmed the guard is CSS-only, mounted once at
      the true root layout, and covers every route including `/onboarding`
      with no gap.
